# P1-4 CLOSEOUT — sidecar side — 2026-09-08

## P1-4 = REJECTED

`kinematic_recovery.py` is **rejected for production**. `--recovery` defaults to **off**. The module
stays on disk, marked `REJECTED / EXPERIMENTAL / NOT FOR SHIPPING`, for forensic reference only.

This supersedes ADR-P008's "READY WITH CONDITIONS" (see ADR-P009). That verdict came from **offline
replay**; live hardware validation with a human subject contradicted it.

Shipping path:

```text
RTMW3D → depth → P0 filter/caps → P1-1 tracker → P1-2 latest-frame → UDP
```

P1-4 is **not** in that chain unless someone explicitly passes `--recovery`, which now prints a
three-line warning banner.

> Full evidence, including the Unity avatar measurements that decided this, is in the Unity repo:
> `docs/P1_4_CLOSEOUT_2026-09-08.md`. This document covers the **sidecar's** responsibilities:
> what changed here, and why the algorithm cannot work on this pipeline's data.

---

## 1. Why it failed — the arithmetic

P1-4 rejects a joint when a bone's length deviates too far from its learned median. On this pipeline
that signal is **smaller than its own noise**:

```text
corruption we must detect (0.85 m knee displacement)   relLenErr ~ 1.50
natural variation on CLEAN human capture, p99                   = 1.791
shipping seg_reject threshold                                   = 1.80
```

A real 0.85 m fault perturbs bone length *less* than ordinary healthy motion already does. There is no
threshold that both catches the fault and avoids false positives — ADR-P008 already measured that
`seg_reject = 0.45` fires on **25.3%** of clean joint-frames.

Compounding it: P0-2's `--leg-max-jump 0.35` slews a teleport across several frames, so the rolling
median **learns** the corrupted length rather than rejecting it.

Measured consequence — the controlled block-8 injection, the only fully controlled comparison:

| pass | wire error | `GEOMETRIC_REJECT` | `RECONSTRUCT` |
|---|---|---|---|
| baseline `--no-recovery` (drift / teleport) | 0.8388 / 0.8542 m | 0 | 0 |
| **`--recovery` (drift / teleport)** | **0.8419 / 0.8439 m** | **0** | **0** |

**P1-4 never fired on the case it was built for.**

Rejections that *did* fire were 87% bone-length driven (`segment` 1001 / `angle` 128), at `relLenErr`
1.817 against a 1.80 threshold — i.e. at the noise floor. The scale-free angle check is the only part
that behaved.

Reconstruction, when it ran (41 times — it was **not** dormant, contrary to the pre-closeout report),
displaced joints by mean **2.19 m** / max **4.16 m** on `left_knee`.

### TEST-ONLY addition, retained

`--inject-drift-file <path>` — polls a JSON spec `{mode, joint, meters, frames}`, applies it to one
joint at high confidence **upstream of P1-1 and P1-4**, then deletes the file. Default off. This is how
the controlled corruption test is produced; without it "does the pipeline catch a confidently-wrong
joint?" cannot be answered on live hardware. **Never enable in production** — it deliberately
falsifies measurements.

## 3. Rollback verification (live, human subject)

Run with **no recovery flag** (`blocks.json` records `recovery: ""`). P1-4 fully inert: 0
`GEOMETRIC_REJECT`, 0 `RECONSTRUCT`, 0 `RECOVERING`, 0 `stage=P1-4` events out of 9921.

Blocks 1–8, per pose (render-rate independent):

| metric | baseline | P1-4 | **rollback** |
|---|---|---|---|
| P0 limb-held | 0.28% | 15.84% | **0.14%** |
| LOST episodes | 1 | 111 | **1** |
| snaps > 45°/pose | 12 | 20 | **13** |
| rotation p99 | 35.61° | 34.92° | **34.27°** |
| tracker CPU p50 / p99 | 0.173 / 0.284 ms | 0.329 / 0.550 ms | **0.175 / 0.310 ms** |
| latency p50 | 39.1 ms | 42.2 ms | **40.8 ms** |
| packet loss | 0 | 0 | **0** (4859/4859) |

Baseline restored; P1-4's CPU cost is gone.

Two residuals, stimulus not regression: the rollback run had **1.48×** more input motion than the
baseline (which raises p95 to 16.32° while the tails stay at baseline), and block 9 is excluded because
the operator achieved *genuine* total occlusion there (116 frames below 0.5 coverage vs **0** in the
baseline run), so its 151 LOST events are correct behaviour, not a regression.

Tests: **P1-1 37/37**, **P1-4 39/39** (retained), Unity EditMode **47/47**, 0 compile errors.

## 4. Rules going forward

```text
DO NOT continue threshold tuning.
DO NOT add more smoothing.
DO NOT add more heuristic rejection layers on the same unstable signal.
```

**Skeleton-level kinematic reconstruction cannot currently be made reliable using the present landmark
geometry, because the bone-length signal's natural variation overlaps the corruption signal we need to
detect.**

Next: an **audit** of F-08 / confidence normalization and upstream landmark/depth metric stability —
why high-confidence wrong joints stay high-confidence, why bone lengths fluctuate so strongly, and why
geometry can become physically impossible while confidence stays high. **Produce findings, not code.**
